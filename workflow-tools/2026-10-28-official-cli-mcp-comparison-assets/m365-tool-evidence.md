# Microsoft 365 CLI and MCP evidence

Reviewed on 2026-10-28. This research supports a comparison for a CUBRID developer who uses Teams, GitHub CI, and a remote Linux host. Usefulness ratings below are judgments for that workflow. Repository statistics are collected separately by the parent agent.

## Important classification results

- **Work IQ has a public MIT-licensed plugin repository, but its distributed CLI is proprietary.** The npm package declares `SEE EULA`. Microsoft Learn explicitly calls Work IQ a proprietary tool. A public GitHub repository does not establish that the CLI or hosted service is open source. [Repository license](https://github.com/microsoft/work-iq/blob/main/LICENSE), [npm metadata](https://registry.npmjs.org/@microsoft%2fworkiq/latest), [CLI documentation, Provide feedback](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/cli#provide-feedback).
- **The current Teams Developer CLI source is in `microsoft/teams-sdk/packages/cli`.** The TypeScript SDK is in the separate `microsoft/teams.ts` repository. The CLI package identifies its name as `@microsoft/teams.cli`, its executable as `teams`, and its license as MIT. [Package manifest](https://github.com/microsoft/teams-sdk/blob/main/packages/cli/package.json), [CLI source](https://github.com/microsoft/teams-sdk/tree/main/packages/cli/src), [repository license](https://github.com/microsoft/teams-sdk/blob/main/LICENSE).
- GitHub's automated SPDX field returned `NOASSERTION` for some repositories. Direct `gh api .../contents/...` reads confirmed MIT text in `microsoft/work-iq/LICENSE`, `microsoftgraph/msgraph-sdk-powershell/LICENSE.txt`, and `OfficeDev/microsoft-365-agents-toolkit/LICENSE`. The content agrees with the connector's file reads.
- **PnP CLI and its MCP adapter are community projects.** Their official project description says the CLI is not affiliated with Microsoft and does not receive Microsoft product support. [Project description](https://github.com/pnp/cli-microsoft365#Microsoft-365--Power-Platform-Community).

### Work IQ sources and discrepancies

The [CLI documentation](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/cli) describes data types and modes at lines 31–58, billing and consent at lines 59–68, Linux support at lines 69–76, GA support at lines 81–83, and proprietary status at lines 259–261 in the fetched page. It says Work IQ reached GA on 2026-06-16, while the GitHub README still contains a public-preview banner. Treat maturity statements as component-specific and prefer the current product documentation for supported CLI builds.

The [Work IQ API overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview#authentication-and-security) describes delegated-only authentication at lines 224–231. Its [licensing section](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview#licensing-requirements) describes Copilot Credits usage billing. The [Work IQ overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/#access-and-pricing) says API access is independent of a Microsoft 365 Copilot license. Therefore do not claim that a Copilot seat alone includes free third-party CLI usage.

Live npm metadata on the review date returned `license: SEE EULA` and version `1.0.1` for `@microsoft/workiq`. The repository's root consists largely of plugin definitions, skills, scripts, docs, and tests. It does not establish a public source tree for the distributed CLI implementation.

### Graph PowerShell sources

- [Overview](https://learn.microsoft.com/en-us/powershell/microsoftgraph/overview?view=graph-powershell-1.0): cross-platform PowerShell 7 support and Graph API coverage.
- [Authentication commands](https://learn.microsoft.com/en-us/powershell/microsoftgraph/authentication-commands?view=graph-powershell-1.0): delegated and app-only authentication at lines 30–35, device-code flow at lines 38–50, certificates at lines 82–85, and custom app usage at lines 56–80.
- [Channel list API](https://learn.microsoft.com/en-us/graph/api/channel-list-messages?view=graph-rest-1.0): root messages and separate replies at lines 31–35, permissions at lines 45–56, and pagination/expansion at lines 61–68. An ordinary channel message list is not automatically a complete transcript.
- [Permission reference](https://learn.microsoft.com/en-us/graph/permissions-reference#channelmessagereadall): `ChannelMessage.Read.All` has `AdminConsentRequired: Yes` for delegated and application permission types.

### Teams CLI source details

The current [CLI manifest](https://github.com/microsoft/teams-sdk/blob/main/packages/cli/package.json#L1) identifies `@microsoft/teams.cli`, executable `teams`, MIT license, repository directory `packages/cli`, and Node.js engine `>=22.12.0`. The [login implementation](https://github.com/microsoft/teams-sdk/blob/main/packages/cli/src/commands/auth/login.ts#L13) defines `--device-code` at line 15. It selects a local browser only for interactive local sessions at line 27.

Live npm metadata reported CLI version `3.0.4`, while the manifest in the fetched default branch reported `3.0.0`. Keep repository activity, package releases, and manifest versions separate.

[Microsoft's announcement](https://devblogs.microsoft.com/microsoft365dev/from-prompt-to-production-teams-agent-setup-simplified/) explains the app registration/configuration workflow. This is evidence for a development tool, not evidence that it retrieves all existing channel history.

### Azure sources and source boundaries

The [Azure CLI interactive login guide](https://learn.microsoft.com/en-us/cli/azure/authenticate-azure-cli-interactively) describes MFA requirements and device-code login. This covers the client sign-in method, not authority to access every Azure resource.

The Azure MCP [source README](https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/README.md) identifies the component and supports manual configurations for different clients. The [authentication design](https://github.com/microsoft/mcp/blob/main/docs/Authentication.md#local-authentication-stdio-transport) states that local outbound Azure authentication uses available credentials and requires RBAC. Its table at lines 6–8 separates local inbound STDIO access from outbound Azure authentication. Lines 50–52 require the authenticated identity to have appropriate Azure roles.

The [overview page](https://learn.microsoft.com/en-us/azure/developer/azure-mcp-server/overview) lists a Copilot subscription among prerequisites, but the source README offers generic MCP client configurations. Treat the Copilot requirement as relevant to Copilot-based hosts instead of labeling the MIT server itself Copilot-only.

## Retired tool appendix

**Microsoft Graph CLI**, [microsoftgraph/msgraph-cli](https://github.com/microsoftgraph/msgraph-cli), remains an open-source repository but is unsuitable for a new integration. Microsoft's [retirement notice](https://devblogs.microsoft.com/microsoft365dev/microsoft-graph-cli-retirement/) states deprecation began on 2025-09-01 and retirement was planned for 2026-08-28. The notice recommends Microsoft Graph PowerShell. On this review date the announced retirement date has passed. Cite the published retirement schedule rather than inferring support from recent repository timestamps.

## Interpretation for the CUBRID workflow

The immediate goal is to read existing Issue Task posts and replies. Work IQ directly fits that goal after tenant and billing setup. Graph PowerShell is useful for an authorized, durable collector. Teams CLI, `atk`, and `a365` become useful when the goal expands to building or governing an agent inside Teams. Azure CLI and Azure MCP become useful if Azure hosts the collector or related infrastructure. None of these clients alone establishes complete collection, duplicate handling, current incident state, or recurring execution.

No software was installed. No account was authenticated. No tenant, cloud resource, or Teams message was changed.
