# Git submodule

상위 저장소가 하위 저장소의 특정 커밋을 기록하는 구조와 일반적인 작업 흐름을 설명합니다.

[HTML 가이드](index.html)를 내려받아 브라우저에서 여세요. GitHub의 파일 화면에서는 HTML 소스가 표시됩니다. 가이드는 외부 스크립트 없이 동작합니다.

## 다루는 내용

- 독립된 저장소와 이력, `.gitmodules`, gitlink의 역할
- 커밋 포인터를 비교하는 단계별 실험
- 서브모듈 추가와 최초 clone
- 팀 변경사항 받기, `update`와 `update --remote`의 차이
- 하위 코드 수정, 상위 참조 커밋, push·PR 순서
- 상태 표시, detached HEAD, URL 변경, 참조 충돌과 제거
- 목적별 명령어와 Git 공식 문서 링크

## 사용 방법

- 상단 목차로 이동합니다.
- 다이어그램의 확대·축소·크게 보기 버튼을 사용합니다.
- 커밋 포인터 실험의 단계를 눌러 세 위치의 커밋을 비교합니다.
- 코드 블록의 복사 버튼으로 예제 명령을 복사합니다.

명령 예제의 저장소 URL과 파일명은 실제 환경에 맞게 바꿔 사용하세요. HTML 안의 실험은 Git 명령을 실행하지 않습니다.
